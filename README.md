# Gwonvibe Agent Skills

사업·콘텐츠·개발·품질·운영에서 반복해서 사용하는 판단 순서를 정리한 한국어 Agent Skills 18종입니다. Claude Code와 Codex에서 사용할 수 있으며, 특정 유료 도구나 강의 자료 없이 각 스킬을 독립적으로 사용할 수 있습니다.

## 가장 빠른 시작

1. [설치안내](INSTALL.md)에 따라 `skills` 안의 폴더를 설치합니다.
2. 사용 중인 AI 에이전트를 새로 시작합니다.
3. 아래처럼 스킬 이름과 실제 요청을 함께 입력합니다.

```text
$branding을 사용해서 우리 서비스 소개와 실제 제공 기능이 같은 약속을 하는지 검토해줘.
확인할 수 없는 내용은 추정하지 말고 질문으로 남겨줘.
```

Codex에서는 `$스킬이름`, Claude Code에서는 `/스킬이름`으로 직접 부를 수 있습니다. 이름을 쓰지 않아도 요청 내용과 설명이 잘 맞으면 에이전트가 자동으로 선택할 수 있습니다.

## 어떤 스킬을 쓰면 될까

### 사업·브랜드·콘텐츠

| 스킬 | 이럴 때 사용 | 시작 요청 예시 |
|---|---|---|
| `behavioral-science` | 고객 행동과 이탈 이유를 근거 중심으로 해석할 때 | “첫 설정 화면에서 이탈하는 이유를 사실과 가설로 나눠줘.” |
| `bi-solo` | 1인 사업 아이디어를 시작하기 전에 비교할 때 | “이 아이디어 세 개를 같은 기준으로 평가하고 먼저 검증할 하나를 골라줘.” |
| `branding` | 브랜드 약속·미션·비전이 서로 맞는지 볼 때 | “브랜드 소개와 실제 경험이 같은 약속을 하는지 봐줘.” |
| `business-os` | 운영 중인 사업의 가장 큰 병목을 찾을 때 | “방문자는 늘었는데 결제가 그대로야. 먼저 볼 병목을 정해줘.” |
| `concept-design` | 상품·서비스·캠페인의 새 컨셉을 만들 때 | “이 고객 문제를 해결하는 서비스 컨셉 세 가지를 비교해줘.” |
| `content-psychology` | 콘텐츠의 주제·훅·구조·CTA를 설계할 때 | “저장을 목표로 릴스 제목·도입·본문·CTA를 만들어줘.” |
| `digital-product-copy` | 전자책·강의·템플릿의 판매 문구를 쓸 때 | “이 전자책의 판매 페이지를 근거 없는 과장 없이 써줘.” |
| `ebook-writing` | 초보자용 전자책의 목차·원고를 만들 때 | “강의 없이 이해할 수 있는 전자책 목차와 1장 초안을 써줘.” |
| `growth-marketing` | 유입·전환·재구매의 병목과 실험을 정할 때 | “가입은 많은데 결제가 적어. 가장 작은 검증 실험을 짜줘.” |
| `harden` | 계획이나 제안이 실제로 작동할지 강도 점검할 때 | “이 출시 계획의 가정과 실패 경로를 찾아 우선순위를 정해줘.” |
| `moat-audit` | 경쟁자가 따라 하기 어려운 이유를 점검할 때 | “우리 서비스의 방어력과 가장 약한 의존점을 점검해줘.” |
| `pricing-decision-7steps` | 가격 후보와 검증 방법을 정할 때 | “이 강의의 가격 후보를 비교하고 실제 반응을 확인할 방법을 정해줘.” |

### 개발·품질·운영

| 스킬 | 이럴 때 사용 | 시작 요청 예시 |
|---|---|---|
| `dependency-manager` | 패키지 사용 여부·버전·취약점을 점검할 때 | “안 쓰는 패키지 후보를 찾아줘. 아직 제거하지는 마.” |
| `deploy-safety-guard` | 배포 전에 운영 준비와 복구 계획을 확인할 때 | “이 프로젝트를 배포해도 되는지 점검하고 차단 요소를 알려줘.” |
| `error-path-analysis` | 로그인·결제·저장 같은 실패 경로를 점검할 때 | “결제 실패 뒤 중복 결제가 생길 수 있는지 확인해줘.” |
| `performance-checker` | 느린 로딩과 반응 지연의 병목을 측정할 때 | “첫 화면이 느린 원인을 측정하고 가장 큰 병목 하나를 찾아줘.” |
| `security-kit` | 권한·결제·개인정보·업로드의 경계를 점검할 때 | “관리자 기능을 일반 사용자가 실행할 수 없는지 점검해줘.” |
| `site-auditor` | 사이트의 기능·접근성·성능·보안을 함께 볼 때 | “이 사이트의 핵심 기능, 접근성, 성능을 함께 점검해줘.” |

각 스킬 폴더의 `SKILL.md` 끝에는 복사해서 쓸 수 있는 요청 예시가 세 개 이상 들어 있습니다.

## 결과를 더 좋게 만드는 요청법

다음 네 가지 중 알고 있는 것만 함께 적어주세요.

- **대상:** 어떤 상품·콘텐츠·사이트를 다루는지
- **목표:** 이번 작업 뒤 무엇이 달라져야 하는지
- **자료:** 원고, 화면, 수치, 코드처럼 확인할 수 있는 근거
- **범위:** 점검만 할지, 실제 수정까지 원하는지

예를 들어 `사이트가 느려`보다 아래 요청이 더 정확합니다.

```text
$performance-checker를 사용해 모바일 첫 화면이 느린 원인을 확인해줘.
현재 코드는 읽어도 되지만 아직 수정하지 말고,
측정 조건과 가장 큰 병목 하나를 먼저 알려줘.
```

## 알아둘 점

- 스킬은 판단 순서를 제공하지만 없는 고객 자료나 성과를 만들어내지는 않습니다.
- 수정·삭제·배포·외부 발송처럼 결과를 바꾸는 작업은 실행 전에 범위를 확인합니다.
- 결제·로그인·배포는 코드 확인만으로 실제 운영 성공을 증명할 수 없습니다. 가능한 환경에서 별도로 테스트해야 합니다.
- 법률·의료·세무·투자 판단을 대신하는 도구가 아닙니다.
- 도구의 가격·정책·기술 문서는 바뀔 수 있으므로 최신 정보가 중요한 요청은 공식 자료를 다시 확인하세요.

## 스킬이 보이지 않을 때

1. 설치한 폴더 바로 아래에 `SKILL.md`가 있는지 확인합니다.
2. 폴더명과 `SKILL.md`의 `name`이 같은지 확인합니다.
3. 설치 전에 열려 있던 채팅이나 터미널을 닫고 새로 시작합니다.
4. 자동 선택이 안 되면 `$스킬이름` 또는 `/스킬이름`으로 직접 부릅니다.
5. 같은 이름의 기존 스킬이 있다면 어느 위치의 스킬이 우선되는지 확인합니다.
