# 설득 구조와 고객 질문

확인된 상품 정보를 고객이 이해하고 판단할 수 있는 순서로 배치한다. 아래 예시는 **입력 사실 → 카피**의 관계를 보여준다. 예시 속 사실은 현재 상품의 자료가 아니며, 가격·운영 조건은 `hooking-patterns.md`의 가격 절을 따른다.

## 고객 망설임을 살필 위치

실제 관찰과 가설을 구별하고, 해당되는 위치에 확인된 안내를 둔다.

| 위치 | 살펴볼 질문 | 사용할 수 있는 근거 |
|---|---|---|
| 가격 직후 | 무엇이 포함되나요? | 실제 구성·가격·제공 조건 |
| 사용법 설명 | 내가 어떻게 쓰나요? | 실제 사용 순서·샘플·대상 조건 |
| 결제 직전 | 판단할 자료가 있나요? | 공개 가능한 샘플, 맥락이 확인된 후기·성과 |

질문에 답할 자료가 없으면 그 답을 보류한다. “쉽습니다”, “누구나 됩니다”, “환불됩니다”로 빈칸을 대신하지 않는다.

## 전체 페이지의 네 가지 역할

고정 섹션이나 필수 순서가 아니다. 같은 문장이 두 역할을 하면 반복하지 않는다. 부분 요청에는 필요한 역할만 쓴다.

1. **상황 짚기:** 제공된 고객의 문제를 알아볼 수 있게 말한다.
2. **사용과 변화 연결:** 상품으로 하는 행동을 보여준다. 측정 결과가 없다면 행동 안내에서 멈춘다.
3. **대상 구체화:** 확인된 고객에게 말을 건다. 초보자를 위한 상품이라는 설명만으로 선수 지식·준비물·기능의 부재를 단정하지 않는다.
4. **망설임에 답하기:** 실제 구성·샘플·조건으로 판단을 돕는다. 모든 걱정을 해소한다는 약속은 필요하지 않다.

### 자료가 적을 때의 연결 예시

**예시 입력:** 첫 강의를 준비하는 사람은 수업 순서 정하기를 어려워한다. “첫 수업 설계 노트”는 PDF 16쪽, 설계 질문 8개와 작성 예시 2개를 담았다. 질문에 답하며 수업 순서를 정리하도록 돕는다. 가격은 9,000원이다. 예시 파일·고객 후기는 아직 받지 않았다.

**이 자료로 쓸 수 있는 초안:**

> 첫 수업, 무엇부터 설명할지 막막한가요?
>
> 설계 질문에 답하며 수업 순서를 정리해 보세요.
> “첫 수업 설계 노트”에는 질문 8개와 작성 예시 2개가 담겨 있습니다.
>
> PDF 16쪽 · 9,000원
> [수업 설계 노트 구매하기]

위 입력만으로는 “질문마다 예시를 보며 따라 쓰세요”, “평생 다운로드”, “추가 결제 없음”을 쓸 수 없다. 예시의 대응 관계와 판매 조건은 각각 별도 정보다. 누락된 후기를 메우려고 제작자의 경험을 만들지도 않는다. 초안에 필요한 판매 조건은 운영자 확인 과제로 남긴다.

## 고객 질문별 구체화

| 질문 | 확인된 입력 예시 | 그 범위에서 쓰는 문장 |
|---|---|---|
| 무엇이 좋아요? | 일정 시트에 날짜·업무·담당자 칸이 있음 | “날짜와 업무, 담당자를 한 표에 적어보세요.” |
| 어떻게 써요? | 회고 워크북 첫 쪽에 오늘의 기분, 다음 쪽에 이번 주 목표를 쓰도록 안내 | “첫 쪽에는 오늘 기분을, 다음 쪽에는 이번 주 목표를 적습니다.” |
| 처음인데 써도 되나요? | 기초 설명부터 시작하며 사전 수강 조건이 없다고 운영자가 확인 | “기초 설명부터 시작합니다. 사전 수강 조건은 없습니다.” |
| 효과는 확인됐나요? | 사용 후기 1건에 ‘회의 준비가 30분에서 20분으로 줄었다’고 기록 | “한 사용자는 회의 준비가 30분에서 20분으로 줄었다고 전했습니다.” — 해당 후기의 조건·맥락을 함께 보존 |

후기는 그 사람의 사례이지 모든 구매자의 결과가 아니다. 입력에 수치가 없을 때는 숫자를 골라 채우는 대신 실제 구성·사용법을 쓴다.

## 신뢰 근거 선택

- **구성과 샘플:** 목록만 받았다면 목록까지만 설명한다. 샘플을 실제로 확인했을 때만 내용·외형·사용 관계를 묘사한다. 수록된 예시가 있다는 사실과 구매 전 공개된다는 사실은 다르다.
- **제작자:** 직접 확인한 경험·과정·경력만 소개한다. 제작자의 말이 없으면 “저도 그랬어요”, “그래서 만들었어요”를 넣지 않는다.
- **외부 근거:** 실제 후기·구매 집계·운영 기간·수상·보도·기업 고객·재구매 자료가 있을 때 출처와 의미를 보존한다. 근거의 권위나 숫자 크기보다 현재 상품과의 관련성을 본다.

이 중 없는 항목은 생략한다. 증거 섹션을 완성하기 위해 다른 종류의 사실을 창작하지 않는다.

## 사용 장면 만들기

구체성은 **장소·행동·확인된 구성**으로 만든다. 시간은 “퇴근 후” 같은 사용 맥락과 “5분이면 완성” 같은 성과 주장을 구별한다. 고객의 바람을 상품의 보장으로 바꾸지 않는다.

| 실제로 확인된 상품 기능 | 가능한 사용 장면 표현 |
|---|---|
| 전자책에 발표 전 확인 질문이 있음 | “발표를 준비할 때, 확인 질문을 펼쳐보세요.” |
| 템플릿에 상품명·고객 문제 입력란이 있음 | “빈칸에 내 상품명과 고객 문제를 적어보세요.” |
| 강의 첫 실습이 소개 글 작성임 | “첫 실습에서 내 소개 글을 작성합니다.” |
| 워크북에 하루 회고 질문이 있음 | “하루를 마치며 회고 질문에 답해보세요.” |
| 코칭에서 제출한 제안서에 개별 피드백을 제공함 | “제출한 제안서를 바탕으로 개별 피드백을 받습니다.” |

이 장면들이 완료 시간·고객 반응·수익·습관 형성까지 입증하지는 않는다. 실제 확인된 결과가 따로 있을 때만 연결한다.

## 섹션 연결

전환 문장도 사실을 새로 추가하지 않는 범위에서 쓴다.

- 상황 → 구성: “이럴 때 사용할 수 있도록 다음 내용을 담았습니다.” — 해당 용도·구성이 확인된 경우.
- 구성 → 사용법: “이렇게 사용합니다.” — 실제 사용법이 있는 경우.
- 사용법 → 증거: “실제 사용자의 이야기입니다.” — 실제 후기가 있을 때만.
- 구성 → 가격: “구성과 가격을 확인해 주세요.” — 공개된 구성을 가격과 연결.
- 가격 → CTA: 버튼의 실제 구매·신청 행동으로 연결. 가격을 썼다는 이유로 즉시 다운로드·무기한 이용을 붙이지 않는다.

자연스러운 연결이 이미 되면 연결어를 추가하지 않는다.
