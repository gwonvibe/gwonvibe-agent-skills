# 후킹 패턴과 가격 표현

아래는 문장 구조를 고르는 참고 자료다. 고객 반응을 보장하는 공식이 아니다. 수치·경험·성과·할인 문구는 가상 예시이며 사용자 상품의 사실로 복사하지 않는다.

## 첫 문장 패턴

### 1. 문제 짚기

**구조:** 구체적 상황 + 질문 또는 장면.

- “매일 할 일 밀려서, 결국 주말마다 잔업하게 되나요?”
- “콘텐츠는 계속 올리는데, 구매 전환이 잘 안되시나요?”
- “SNS 글 하나 쓰는 데 2시간씩 붙잡고 계시나요?”

고객 문제가 확인돼 있을 때 쓴다. 장소·행동으로 구체화하되 실제 고객의 시간이나 고통을 추정해 단정하지 않는다.

### 2. 숫자 비교

**구조:** 확인된 현재 시간·노력 → 확인된 변화.

- “하루 2시간 야근, 5분으로 줄이는 템플릿”
- “소개글 하나에 3시간 걸리던 게 30분으로 줄어요”
- “매주 10시간 → 매주 1시간. 나머지는 자동화”

위 예시는 측정 근거가 있을 때만 쓸 수 있는 형태다. 단위·표본·조건을 보존하고 일부 사례를 보장 효과로 확대하지 않는다. 수치가 없으면 실제 구성·사용 행동을 설명한다.

### 3. 의외성

**구조:** 익숙한 방법의 한계 + 다른 관점.

- “이런 템플릿 쓰면 오히려 시간 더 걸려요”
- “열심히 블로그 쓰는데 왜 매출이 안 오를까요?”
- “좋은 콘텐츠만 만들면 팔린다고요? 아닙니다”

고객이 실제로 쓰는 방법과 그 한계를 알 때 쓴다. 근거 없이 고객이 틀렸다고 몰거나 부정·불안만 남기지 않는다.

### 4. 행동과 사용 장면

**구조:** 간단한 행동 + 이해할 수 있는 변화.

- “이거 하나로, 이젠 매일 6시 칼퇴합니다”
- “템플릿 하나 바꿨을 뿐인데, 문의가 3배 늘었어요”
- “하루 10분 따라 쓰면, 글쓰기 습관이 생겨요”

성과가 확인되지 않았다면 위 결과를 약속하지 않는다. 예컨대 실제 빈칸형 템플릿이면 “빈칸에 내 상품명을 넣어 초안을 시작하세요”처럼 확인된 행동을 쓴다.

## 선택 기준

상품 종류보다 보유 근거로 고른다. 문제는 알지만 결과 수치가 없으면 문제·사용 장면, 비교 수치가 있으면 숫자, 대안의 한계가 확인됐으면 의외성을 검토한다. 여러 패턴을 모든 섹션에 채울 필요는 없다.

## 가격·무료·운영 조건

이 절은 이 스킬의 가격 표현 기준이다. 가격 결정 자체는 pricing-decision-7steps에 해당하는 별도 요청이다.

- 확정 가격·무료 여부·포함 항목·제공 조건을 그대로 설명한다.
- 금전적 회수가 입증된 상품에만 조건을 밝힌 투자 관점을 검토한다. 취미·학습·경험 상품은 실제 사용 가치로 설명하고 수익 회수를 강제하지 않는다.
- 후기의 “3만원으로 15만원 벌었어요” 같은 말은 실제 자료와 맥락이 있을 때만 쓴다. 보수적 추정도 실적이나 보장으로 바꾸지 않는다.
- 할인·가격 인상·마감·정원·환불·체험은 운영자가 확정한 사실만 쓴다. 가격 저항을 낮추려고 새 조건을 약속하지 않는다.
- 환불 미확정은 내부 확인사항으로 분리한다. 괄호의 “확인 필요”를 붙인 정책을 게시 확정 문구로 표시하지 않는다.
- 무료 신청을 유료 결제로 보이게 하거나, 유료 CTA를 무료처럼 보이게 하지 않는다.

### 실제 얼리버드가 있을 때의 표현 예시

| 관점 | 표현 예시 |
|---|---|
| 초기 신뢰에 감사 | “가장 먼저 가치를 알아봐주신 분들께 감사를 담아 얼리버드 가격으로 드려요” |
| 초기 상품의 특성 | “이제 시작이지만 진심을 다해 만들었어요. 가능성을 믿고 함께해주시는 분들께 보답합니다” |
| 진입 부담 완화 | “조금 더 마음 편히 도전하실 수 있도록 낮췄어요” |
| 확정된 인상 일정 | “이번 회차가 끝나면 가격이 높아져요” |

진정성 표현도 실제 제작자의 말·과정에 맞게 사용한다. 낮추지 않은 가격이나 확정되지 않은 인상 일정을 예시 때문에 만들지 않는다.

## 약한 문장을 고칠 때

| 문제 | 확인·수정 |
|---|---|
| “힘드시죠?”처럼 너무 넓음 | 자료에 있는 고객의 장소·행동·상황을 구체화 |
| 큰 숫자만 강조 | 실제 데이터·단위·조건 확인, 없으면 수치 제거 |
| 부정만 하고 대안이 없음 | 확인된 대안·사용법 제시 |
| “좋아져요”처럼 결과가 모호함 | 실제 구성과 사용 장면으로 설명 |
| “시작하기”의 동작이 불명확 | 버튼의 실제 다음 행동을 명시. 가치 설명 때문에 구매·신청 여부를 숨기지 않음 |
