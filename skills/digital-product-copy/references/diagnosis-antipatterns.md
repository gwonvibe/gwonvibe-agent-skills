# 카피 진단과 교정 예시

요청한 범위만 검토한다. 사실·운영 조건을 먼저 확인하고, 표현·가독성을 그다음에 본다. 아래 교정 예시는 문장 구조 비교이며 판매자 실적이 아니다.

## 1. 사실과 조건

- 수치·후기·경력·제작자 경험·제작 계기·샘플 묘사가 입력 자료에 있는지 대조한다. 숫자가 없다는 이유로 창작 경험을 사실로 써도 되는 것은 아니다.
- 구매 후 변화와 구성·사용법의 관계를 확인한다. 실제 성과와 가능한 사용 장면을 구별한다.
- 승인된 가격·무료/유료 구분·제공 범위·환불·주의사항을 보존한다. 없는 보장·실적·마감은 표현을 다듬는 대신 제거하거나 확인 과제로 남긴다.
- 후기의 대상·조건·원래 의미를 보존하고, 없는 후기·샘플을 읽었다고 보고하지 않는다.
- 근거가 미확인인 문장이 남아 있으면 “증거 없는 주장 없음”으로 판정하지 않는다.

## 2. 세 가지 표현 점검

### 상단 이해

누구를 위한 무엇인지, 어떤 행동을 돕는지 읽히는가? “3초”는 빠르게 훑는 요령이다. 자체 검토를 실제 고객의 3초 반응 시험으로 보고하지 않는다.

- 설명형: “이 전자책은 마케팅 전략을 담고 있습니다.”
- 상황형 대안: “콘텐츠는 매일 올리는데, 왜 매출은 안 오를까요?”

어느 쪽이 적절한지는 요청·상품·고객 근거로 판단한다. 모든 첫 문장을 문제 질문으로 바꾸지 않는다.

### 문단과 실제 화면

실제 페이지가 있을 때 필요한 화면 폭에서 확인한다. 375px·3줄은 참고 기준이며 필수 안내를 삭제하는 규칙이 아니다. 텍스트만 있으면 가독성 제안까지만 하고 렌더는 미검증으로 남긴다.

- 덩어리로 보이는 구간은 가독성 후보이지 관찰된 이탈 지점이 아니다.
- 문단을 나누거나 목록으로 바꾸되 구성·조건·주의사항은 유지한다.
- 예: PDF·노션 15개 템플릿이 실제 구성일 때 긴 설명을 “PDF + 노션, 15개 템플릿. 각 항목의 예시를 보고 빈칸을 채웁니다.”로 나눌 수 있다.

### “그래서?”

기능 설명이 고객의 실제 사용에 어떻게 연결되는가? 답이 없으면 구성·사용법을 구체화한다. 결과를 선명하게 하려고 수익·완료 시간을 만들지 않는다.

- “체계적인 커리큘럼” → 확인된 주차별 실제 활동을 설명한다.
- “고품질 템플릿” → 실제 포함 항목·예시·사용 순서를 보여준다.

## 3. 교정 예시

다음 숫자·성과·경력은 **근거가 있을 때만** 가능한 문장 형태다. 근거가 없으면 숫자를 바꿔 채우는 것이 아니라 확인된 구성·행동으로 설명한다.

| 막연한 표현 | 조건부 구체화 예시 |
|---|---|
| 간편하고 편리한 전자책 | “매일 10분 따라 쓰면, 글쓰기 습관이 생겨요” — 시간·효과 근거 필요 |
| 효과적인 마케팅 가이드 | “이 가이드대로 했더니 2주 만에 첫 문의가 왔어요” — 실제 후기와 맥락 필요 |
| 실용적인 업무 템플릿 | “회의록 정리, 이제 5분이면 끝나요” — 측정 조건 필요 |
| 가성비가 좋아요 | “70명이 구매했고, 80%가 재구매했어요” — 실제 집계·분모 필요 |
| 퀄리티가 뛰어나요 | “현직 마케터 3명이 직접 검수했어요” — 실제 검수 근거 필요 |
| 전문가가 만들었어요 | “7년차 PM이 실무에서 쓰던 템플릿 그대로예요” — 제작자 이력·사용 사실 필요 |
| 검증된 방법론 | “127명이 첫 달 평균 47만원을 벌었어요” — 원자료·조건 필요. 없으면 사용 절차 설명 |

### CTA는 설득과 동작을 구별

“구매하기”, “신청하기”, “무료 PDF 받기” 자체는 안티패턴이 아니다. 버튼은 누른 뒤의 행동과 결제 여부를 분명하게 하고, 주변 문장에서 가치를 설명한다.

- 무료 신청 페이지로 이동: “무료 PDF 신청하기”.
- 유료 구매: 확인된 상품명과 결제 행동을 드러낸다.
- “내일부터 달라지는 루틴” 같은 가치 문장만으로 구매·신청 동작을 가리지 않는다.

### 고객 상황과 구성

전체 페이지에서 고객 상황을 먼저 보여주는 방식은 선택지다. 상품 구성만 물었거나 기존 문구 일부를 고치는 요청에는 불필요한 후킹을 추가하지 않는다.

“총 15개의 템플릿”이라는 사실은 버리지 않고, 실제로 빈칸형이라면 “상세페이지 초안을 시작할 수 있는 빈칸형 템플릿 15개”처럼 용도를 연결한다.

## 4. 종료와 보고

해당 항목만 자체 점검한다.

- 사실·가격·무료/유료·제공 조건이 입력과 맞는가?
- 무엇을 누르면 무슨 일이 생기는지 분명한가?
- 구성·사용 장면이 이해되는가?
- 후기 맥락·필수 안내를 압축 때문에 잃지 않았는가?
- 자체 검토·실제 렌더·고객 반응 측정의 범위를 구별했는가?

진단을 요청받았다면 확인된 문제, 필요한 수정, 미확인을 보고한다. 미확인을 억지로 PASS로 바꾸거나 통과할 때까지 무한히 반복하지 않는다. 버튼만 요청했다면 버튼만 제시하고 종료한다.
