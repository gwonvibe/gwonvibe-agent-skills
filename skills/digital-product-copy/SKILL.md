# Digital Product Copy

확인된 상품 정보와 고객의 실제 사용 장면을 연결해, 고객이 **무엇을 받고 어떻게 판단해야 하는지** 이해하게 만드는 스킬이다.

좋은 카피는 빈칸을 그럴듯한 말로 채우는 작업이 아니다.

```text
확인된 사실 + 고객이 쓰는 장면 + 분명한 다음 행동
```

## 요청 범위부터 지킨다

- **전체 페이지:** 필요한 입력을 확인하고 페이지 흐름까지 작성한다.
- **부분 작성:** 제목·버튼·FAQ처럼 요청한 구간과 개수만 작성한다.
- **진단:** 확인된 문제와 최소 수정안을 제시한다.

“버튼 3개만”이면 버튼 3개만 낸다. 사용자가 단계별 승인을 요청했다면 다음 단계로 먼저 넘어가지 않는다.

## 필요한 입력

이미 제공된 대화·문서·확정 결정을 먼저 사용한다.

- 상품명과 유료·무료 여부
- 우선 고객과 고객이 겪는 구체적인 상황
- 실제 구성과 제공 형식
- 확인된 사용 방법
- 가격·제공 기간·환불·주의사항 등 판매 조건
- 공개 가능한 후기·성과·제작자 정보
- 버튼을 누른 뒤 일어나는 실제 행동

전체 초안에 꼭 필요한 공백만 질문한다. 나머지는 추정해 채우지 않고 초안 내부 확인사항으로 남긴다.

## 사실을 다루는 규칙

- 구성 목록은 항목이 존재한다는 사실까지만 알려준다. 내부 특징·효과·추가 비용의 유무를 자동으로 만들지 않는다.
- 실제로 보지 않은 샘플·후기·파일을 본 것처럼 묘사하지 않는다.
- 제작자의 경험·경력·제작 계기도 제공된 자료가 있을 때만 쓴다.
- 제목에 든 시간이나 고객의 희망을 완료 시간·수익·보장된 변화로 바꾸지 않는다.
- 가격·할인·마감·정원·환불·무료 제공 조건을 새로 약속하지 않는다.
- 근거 없는 주장은 약하게 표현해 남기지 말고 제거하거나 내부 확인사항으로 분리한다.

## 작성 순서

### 1. 사실과 미확인 분리

상품 구성·사용법·증거·판매 조건을 `확인됨 / 미확인`으로 나눈다. 이 표는 작업 기준이며 사용자가 요청하지 않으면 출력하지 않는다.

### 2. 사실 블록 먼저 작성

입력의 명칭·수량·가격·조건을 보존한다.

예: `회고 질문 8개와 작성 예시 2개`를 받았다면 그대로 쓴다. `각 질문에 맞춘 예시`라고 확장하려면 실제 대응 관계가 확인돼야 한다.

### 3. 고객 상황과 사용 장면 연결

막연한 형용사보다 장소·행동·확인된 구성을 사용한다.

- 막연함: “실용적인 업무 템플릿”
- 구체화: “빈칸에 상품명과 고객 문제를 적어 상세페이지 초안을 시작하세요.”

결과 수치가 없다면 실제로 하는 행동까지만 설명한다.

### 4. 필요한 페이지 흐름 구성

전체 페이지를 요청받았을 때만 다음 역할 중 필요한 것을 고른다.

1. 고객이 알아볼 수 있는 상황
2. 상품으로 하는 행동과 얻는 변화
3. 실제 구성과 사용 방법
4. 판단에 필요한 샘플·후기·제작자 근거
5. 가격·제공 조건·주의사항
6. 구매·신청 행동이 분명한 CTA
7. 실제 망설임에 답하는 FAQ

자료가 없는 섹션은 만들지 않는다. 환불·희소성·손실·사회적 증거를 판매 페이지 필수 요소로 취급하지 않는다.

### 5. 제출 전 대조

완성된 문장의 상품 주장마다 입력 근거가 있는지 확인한다. 미확인 내용은 게시용 본문에서 제거하거나 운영자가 확인할 내부 메모로 분리한다.

## 표현 기준

- 헤드라인은 기본적으로 해요체, CTA는 행동형, 설명·FAQ는 합니다체를 사용하되 기존 브랜드 톤을 우선한다.
- 버튼에는 `구매하기`, `신청하기`, `무료 PDF 받기`처럼 다음 행동과 결제 여부를 드러낸다.
- 긴 문단은 나누되 구성·환불·주의사항을 가독성 때문에 삭제하지 않는다.
- 실제 화면을 보지 않았다면 모바일 줄 수나 이탈 지점을 확인했다고 말하지 않는다.
- 고객 반응·전환 효과는 실제 측정 전까지 가설이다.

- 전체 설득 흐름과 고객 질문: `references/persuasion-structure.md`

## 출력

요청한 카피를 먼저 제시한다. 필요한 경우에만 아래를 덧붙인다.

- 게시 전에 확인할 미정 조건
- 근거 부족으로 제외한 주장
- 실제 화면이나 고객 반응을 확인하지 못한 범위

## 요청 예시

- “이 전자책의 판매 페이지 초안을 써줘. 확인되지 않은 후기나 효과는 만들지 마.”
- “무료 체크리스트 신청 버튼 문구만 5개 만들어줘.”
- “이 강의 상세페이지에서 근거 없는 주장과 실제 구성의 연결이 약한 부분만 찾아줘.”
- “환불 조건은 아직 미정이야. 게시 문구로 확정하지 말고 내부 확인사항으로 남겨줘.”
