# 경쟁우위 방어력 점검

좋아 보이는 차별점이 아니라 경쟁자가 공개된 결과물을 따라 해도 고객이 그대로 옮겨가지 않는 이유를 찾는다. 증거가 없으면 “없음”으로 단정하지 않고 미확인으로 남긴다.

## 초보자를 위한 용어

- **경쟁우위**: 고객이 다른 선택지보다 우리를 고를 이유다.
- **해자**: 성 주위의 물길처럼 경쟁자가 쉽게 넘어오지 못하게 하는 구조다. 좋은 기능 하나보다 시간이 지나며 쌓이는 고객 관계, 데이터, 운영 방식에 가깝다.
- **전환 부담**: 고객이 다른 상품으로 옮길 때 다시 배우거나 옮겨야 하는 자료·설정·관계다. 고객을 불편하게 가두는 것과는 다르다.
- **네트워크 효과**: 사용자가 늘수록 기존 사용자에게도 가치가 커지는 현상이다. 사람이 많은 식당이 단순히 유명한 것과 달리, 참여자가 늘어 서로에게 직접 도움이 되어야 한다.
- **단일 의존점**: 하나가 멈추면 사업 전체가 크게 흔들리는 플랫폼, 고객, 계정, 공급자다.

## 먼저 지킬 원칙

- 실력, 성실함, 열정, 빠른 작업만으로 해자라고 부르지 않는다. 그것이 기록·관계·데이터·시스템으로 축적되는지 본다.
- 사용자 설명, 실제 기록, 측정값을 구분한다.
- 높은 매출이나 재구매율만으로 원인을 단정하지 않는다.
- 같은 증거를 여러 유형에 중복해 방어력을 부풀리지 않는다.
- 자료 부족은 `미확인`, 실제로 없다는 근거는 `없음`으로 구분한다.
- 해자는 고객을 가두거나 개인정보를 과도하게 모으는 핑계가 아니다.
- 감사 요청만으로 계약, 가격, 채널, 데이터 수집 방식을 변경하지 않는다.

## 적용 범위

고객 반응, 매출, 사용 기록, 오디언스처럼 확인할 운영 자료가 있는 사업에 가장 잘 맞는다.

아직 시작 전이라면 해자 점수를 만들지 않는다. 대신 앞으로 검증할 경쟁우위 가설과 필요한 증거만 정리한다.

## 1. 사업 스냅샷

이미 있는 정보는 다시 묻지 않는다. 판단에 필요한 항목만 정리한다.

```text
주요 고객:
고객이 선택하는 이유:
주요 상품과 매출원:
고객이 들어오는 경로:
재구매·유지·추천 기록:
경쟁자가 볼 수 있는 공개 요소:
우리만 가진 비공개 자산:
한 곳에 집중된 의존성:
```

원문이나 기록을 보지 못했다면 “사용자 설명 기준”이라고 표시한다.

## 2. 모방 테스트

```text
비슷한 자원과 실력을 가진 경쟁자가
우리의 공개 콘텐츠, 상품 구성, 화면, 가격을 본다면
무엇을 쉽게 따라 할 수 있고 무엇은 바로 만들 수 없는가?
```

따라 하기 어려운 이유를 “브랜드라서”, “퀄리티가 높아서”처럼 쓰지 않는다. 어떤 자산이 얼마나 축적됐고 고객 행동에 어떻게 연결되는지 적는다.

복제가 어려운 기간을 임의로 고정하지 않는다. 해당 업계에서 고객이 대안을 만들거나 바꾸는 데 걸리는 현실적인 시간과 비용을 본다.

## 3. 여섯 가지 관점

각 항목을 `확인됨 / 약한 신호 / 미확인 / 없음` 중 하나로 표시한다.

| 관점 | 판단 질문 | 확인할 증거 예시 |
|---|---|---|
| 고객 축적 | 고객이 옮길 때 다시 만들어야 할 가치 있는 자료·설정·학습이 있는가 | 이관 자료, 사용 이력, 유지·이탈 기록 |
| 직접 도달 | 플랫폼 추천 없이도 고객에게 다시 닿을 수 있는가 | 동의받은 이메일, 자체 사이트 재방문, 직접 문의 |
| 신뢰와 평판 | 축적된 실적과 평판이 실제 선택을 돕는가 | 지명 문의, 검증 가능한 후기, 반복 추천 |
| 희소한 자원 | 다른 곳에서 쉽게 구할 수 없는 합법적인 자산이 있는가 | 계약, 허가, 고유 데이터, 파트너 관계 |
| 운영 시스템 | 같은 품질을 더 안정적이거나 효율적으로 제공하는 방식이 있는가 | 작업 기록, 오류율, 원가, 처리 시간 비교 |
| 참여자 가치 | 참여자가 늘수록 기존 참여자의 결과도 좋아지는가 | 사용자 간 거래·협업·답변·데이터 기여 기록 |

### 판정 기준

- **확인됨**: 실제 기록이나 측정값이 있고, 그 자산이 고객 선택이나 운영 결과에 연결된 이유를 설명할 수 있다.
- **약한 신호**: 관련 기록은 있지만 반복성이나 원인 연결이 아직 부족하다.
- **미확인**: 확인할 자료가 없거나 측정하지 않았다.
- **없음**: 현재 구조에 해당 자산이 없다는 자료나 운영 사실이 있다.

예를 들어 재구매율이 높아도 고객 축적 때문인지 상품 만족 때문인지 알 수 없다면, 전환 부담이 확인됐다고 말하지 않는다.

## 4. 의존성 점검

확인된 경쟁우위가 누구의 통제 아래 있는지 본다.

```text
의존 대상:
매출·유입·운영에서 차지하는 비중:
우리가 통제할 수 있는 것:
상대가 정책을 바꾸거나 멈추면 생기는 일:
대체 경로와 복구 시간:
```

특정 비율을 넘었다는 이유만으로 자동 판정하지 않는다. 비중이 크고, 우리가 통제할 수 없으며, 대체 경로도 없을수록 위험이 크다.

플랫폼 팔로워처럼 빌린 채널은 그 자체로 직접 도달 자산이라고 보지 않는다. 다만 실제로 다른 채널이나 구매 관계로 이어지는 기록이 있다면 그 연결은 별도로 평가한다.

## 5. 강화 행동 고르기

가장 많은 아이디어보다 현재 약한 연결 하나를 강화할 행동을 고른다.

```text
강화할 관점:
현재 증거:
부족한 연결:
가장 작은 행동:
필요한 시간·비용·권한:
확인할 지표 또는 기록:
판단 시점:
중단 조건:
```

사용자가 제약을 주지 않았다면 시간과 비용을 임의로 정하지 않는다. 실행 전에 실제 자원과 승인 범위를 확인한다.

## 출력 형식

```markdown
## 한 줄 판정
- 확인된 경쟁우위:
- 약한 신호:
- 미확인 영역:
- 가장 큰 의존 위험:

## 관점별 점검
| 관점 | 판정 | 증거 | 고객·운영 결과와의 연결 | 의존 위험 |
|---|---|---|---|---|

## 가장 먼저 강화할 것
- 대상:
- 선택 이유:
- 가장 작은 행동:
- 확인 방법:

## 과대평가하기 쉬운 주장
- [실제 자료에 등장한 주장만 작성]

## 확인하지 못한 범위
- [추가 자료나 실제 고객 검증이 필요한 부분]
```

형식을 채우기 위해 고객의 주장이나 착각을 만들어내지 않는다.

## 초보자가 바로 쓸 요청 예시

```text
내 사업이 경쟁자에게 쉽게 복제될 수 있는지 점검해줘.
내 설명만으로 확인된 것처럼 말하지 말고,
실제 자료가 필요한 부분은 미확인으로 표시해줘.
```

```text
매출 대부분이 한 플랫폼에서 나오고 고객 이메일은 따로 없어.
이 상황에서 내가 가진 경쟁우위와 플랫폼 의존 위험을 구분하고,
가장 먼저 확인하거나 강화할 행동 하나를 제안해줘.
실제 고객 연락이나 데이터 수집은 하지 말아줘.
```

```text
아직 출시 전인 서비스야. 해자가 있다고 점수 매기지 말고,
경쟁우위 가설과 출시 후 어떤 증거를 모아야 하는지만 정리해줘.
```
