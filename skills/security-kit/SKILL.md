# 보안 경계 설계와 점검

보안을 긴 체크리스트나 도구 점수로 대신하지 않는다. 보호할 데이터와 행동을 정하고, 누가 어디까지 믿을 수 있는지 확인한 뒤 실제 실패·변조 경로를 검증한다.

## 초보자를 위한 용어

- **인증**: 요청한 사람이 누구인지 확인하는 일이다. 건물 입구에서 신분증을 확인하는 것과 같다.
- **권한 확인**: 확인된 사람이 이 방이나 문서를 사용할 수 있는지 판단하는 일이다. 신분증이 있어도 모든 방에 들어갈 수는 없다.
- **신뢰 경계**: 믿을 수 있는 영역과 외부 입력이 만나는 선이다. 브라우저에서 서버로 넘어오는 값은 사용자가 바꿀 수 있다고 본다.
- **최소 권한**: 작업에 필요한 만큼만 권한을 주는 원칙이다.
- **입력 검증**: 허용할 필드, 형식, 길이, 범위를 확인하는 일이다.
- **정제**: 허용된 입력 안에서도 화면이나 문서에서 위험하게 해석될 내용을 안전한 형태로 바꾸는 일이다.
- **행 단위 접근 제어**: 데이터베이스의 각 행을 누가 읽고 바꿀 수 있는지 제한하는 규칙이다.
- **멱등성**: 같은 요청이 반복돼도 결제·포인트·예약이 한 번만 처리되는 성질이다.

## 사용할 때

- 로그인, 역할, 관리자 기능, 리소스 소유권
- 가격, 결제, 크레딧, 환불
- 개인정보, 민감정보, API 키와 시크릿
- 파일 업로드, 사용자 HTML, 사용자 입력 URL
- 웹훅과 외부 서비스 연동
- 삭제, 권한 변경, 대량 수정처럼 복구하기 어려운 작업

일반 화면 문구나 스타일 변경에 별도 보안 문서를 만들지 않는다.

## 먼저 지킬 원칙

- 로그인 여부만 확인하고 권한 검사를 생략하지 않는다.
- 가격, 금액, 역할, 소유자, 승인 상태는 브라우저가 보낸 값을 그대로 믿지 않는다.
- 외부 입력 객체 전체를 데이터베이스 저장 함수에 넘기지 않는다. 허용한 필드만 새 객체로 만든다.
- 시크릿과 서버 전용 환경변수를 브라우저 코드, 응답, 로그에 넣지 않는다.
- 개인정보와 인증정보를 기본적으로 로그에 남기지 않는다.
- 오류 응답에 내부 스택, 쿼리, 연결 문자열, 시크릿을 포함하지 않는다.
- 자동 스캐너나 문자열 검색을 통과했다는 이유로 안전하다고 말하지 않는다.
- 보안 기능 구현과 실제 권한 테스트는 사용자가 요청한 범위 안에서만 수행한다.
- 운영 계정, 실제 결제, 실제 이메일, 운영 데이터 변경이 필요한 테스트는 대상과 복구 방법을 확인하고 별도 승인을 받는다.

## 1. 보호할 것을 정한다

```text
보호할 데이터:
보호할 행동:
허용된 사용자와 역할:
절대 허용하면 안 되는 사용자:
금액·권한·개인정보가 바뀌는 지점:
외부 서비스와 주고받는 정보:
실패했을 때 가장 큰 피해:
```

기능 전체를 추상적으로 “안전하게” 만들려 하지 말고 민감한 경계를 특정한다.

## 2. 요청 흐름을 따라간다

```text
사용자 화면 → 서버 경계 → 권한 확인 → 데이터 처리 → 외부 서비스 → 응답·로그
```

각 지점에서 다음을 확인한다.

### 사용자와 권한

- 서버가 실제 세션이나 토큰을 검증하는가
- 요청한 사용자가 해당 데이터의 소유자이거나 허용된 역할인지 확인하는가
- 관리자 권한이 화면 숨김이 아니라 서버에서도 검사되는가
- 기본값은 허용이 아니라 거부인가
- 데이터베이스 정책과 실제 역할 권한이 함께 제한되는가

행 단위 접근 제어가 켜져 있어도 넓은 테이블 권한이나 서버 관리자 키로 우회될 수 있다. 설정 하나만 보고 격리가 검증됐다고 말하지 않는다.

### 입력

- 허용할 필드만 선택하는가
- 자료형, 길이, 범위, 개수가 제한되는가
- 가격과 할인은 서버의 상품 정보로 다시 계산하는가
- 데이터베이스 쿼리에 입력을 문자열로 이어 붙이지 않는가
- 명령 실행은 쉘 문자열 대신 명령과 인자를 분리하는가
- 사용자 HTML은 신뢰 가능한 방식으로 정제하는가
- 외부 URL은 허용 대상과 사설 네트워크 접근을 제한하는가

### 파일 업로드

- 확장자뿐 아니라 실제 파일 형식과 크기를 확인하는가
- 저장 이름을 사용자가 직접 결정하지 않는가
- 실행 가능한 위치에 그대로 저장하지 않는가
- 공개 범위와 다운로드 권한이 맞는가
- 압축 해제나 변환 작업에 크기·시간 제한이 있는가

### 데이터와 시크릿

- 필요한 정보만 수집하는가
- 저장·보관·삭제 기준이 실제 운영과 맞는가
- 암호화가 필요한 구간과 키 관리 주체가 정해졌는가
- 백업과 분석 도구에도 같은 보호가 적용되는가
- 클라이언트 번들, 소스맵, 오류 추적 도구에 시크릿이 들어가지 않는가

## 3. 금액과 중복 실행을 확인한다

결제, 크레딧, 쿠폰, 포인트, 예약, 웹훅은 다음을 확인한다.

- 금액과 상태를 서버가 결정하는가
- 외부 결제·웹훅의 발신자와 요청 내용이 검증되는가
- 같은 이벤트가 여러 번 와도 한 번만 반영되는가
- 일부 단계만 성공했을 때 상태를 조회하고 복구할 수 있는가
- 성공 응답 전에 실제 저장 결과를 확인하는가
- 실패 뒤 무조건 재시도해 중복 상태를 만들지 않는가

## 4. 최소 부정 테스트를 정한다

정상 사용자 테스트만으로 권한 경계를 검증할 수 없다. 해당 기능에 맞는 항목만 선택한다.

```text
로그인하지 않은 요청
다른 사용자의 데이터 식별자로 보낸 요청
권한이 낮은 역할의 관리자 행동 요청
허용하지 않은 필드를 추가한 요청
잘못된 형식·지나치게 큰 입력
같은 상태 변경 요청의 반복
외부 서비스 응답 지연·실패
부분 성공 뒤 다시 실행
오류 응답과 로그의 민감정보 노출
```

테스트는 격리된 환경과 테스트 계정·데이터를 우선한다. 테스트가 실제 사용자나 금액에 영향을 줄 수 있으면 실행하지 않고 필요한 승인과 준비를 보고한다.

## 5. 판정한다

- **즉시 수정**: 무권한 접근, 권한 상승, 시크릿·개인정보 노출, 금액 조작, 파괴적 입력이 현재 코드나 실행 결과로 확인됐다.
- **실행 전 확인**: 영향은 크지만 설정, 운영 환경, 실제 역할 테스트가 부족하다.
- **개선 권장**: 직접 악용 경로는 확인되지 않았지만 방어와 추적이 부족하다.
- **확인 범위 내 문제 없음**: 실행한 범위에서는 문제가 재현되지 않았다. 전체 보안 보장은 아니다.

정적 코드 확인, 테스트 환경 실행, 운영 환경 검증을 구분해서 보고한다.

## 수정할 때

사용자가 수정을 요청한 경우에만 진행한다.

1. 가장 좁은 공통 경계에서 문제를 막는다.
2. 기존 인증·검증 라이브러리와 프로젝트 패턴을 재사용한다.
3. 권한이나 입력 허용 범위를 넓히는 임시 우회를 남기지 않는다.
4. 정상 요청과 최소 부정 테스트를 함께 실행한다.
5. 이번 변경의 파일과 검증 결과만 보고한다.

새 보안 패키지는 기존 방식으로 해결할 수 없고 필요성이 확인됐을 때만 제안한다.

## 출력 형식

```markdown
## 점검한 경계
- 보호할 데이터·행동:
- 사용자·역할:
- 요청 흐름:

## 발견 사항
| 우선순위 | 위치 | 문제 | 악용·실패 조건 | 근거 | 최소 수정 |
|---|---|---|---|---|---|

## 실행한 검증
- 정상 요청:
- 무권한·변조 요청:
- 중복·부분 실패:

## 확인하지 못한 영역
- 운영 설정·외부 서비스·실제 역할 중 미확인 범위:

## 판정
즉시 수정 / 실행 전 확인 / 개선 권장 / 확인 범위 내 문제 없음
```

## 초보자가 바로 쓸 요청 예시

```text
사용자가 자기 예약만 수정할 수 있는 기능을 만들려고 해.
로그인 확인과 소유권 확인을 어디서 해야 하는지,
다른 사람 예약 번호를 보냈을 때 어떻게 막을지 설계해줘.
```

```text
결제 요청에서 브라우저가 보낸 가격을 그대로 쓰는지 점검해줘.
실제 결제는 하지 말고 서버 계산, 중복 요청, 웹훅 검증 경로를 확인해줘.
```

```text
파일 업로드 기능의 보안 경계를 검토하고 필요한 최소 수정을 해줘.
파일 형식·크기·저장 위치·다운로드 권한을 확인한 뒤
테스트 파일로만 검증해줘.
```

## 최신 정보가 필요한 경우

사용 중인 인증 서비스, 데이터베이스, 결제 공급자, 웹 프레임워크의 보안 방식은 바뀔 수 있다. 구체적인 설정과 취약점은 작업 시점의 공식 문서와 보안 공지를 확인한다. 법률·규정 준수 여부는 관할과 실제 데이터 흐름을 확인하지 않고 단정하지 않는다.
