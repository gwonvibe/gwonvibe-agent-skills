# 컨셉 발상 워크숍

기본 절차만으로 후보가 충분하지 않을 때 필요한 질문만 골라 쓴다.

## 과제 재구성 질문

| 관점 | 질문 |
|---|---|
| 부분에서 전체로 | 고객의 앞뒤 과정까지 보면 진짜 막힘은 어디인가? |
| 수단에서 목적으로 | 지금 만들려는 것은 고객이 원하는 결과를 위한 어떤 수단인가? |
| 명사에서 행동으로 | 상품 이름을 빼고 고객이 하려는 행동으로 다시 말하면 무엇인가? |
| 현재에서 이상으로 | 현재 제약 하나가 사라지면 어떤 경험이 가능해지는가? |
| 추가에서 제거로 | 무엇을 더하기보다 없애야 할 불편·대기·불안은 무엇인가? |
| 평균에서 갈등으로 | 고객이 원하면서 동시에 피하고 싶은 것은 무엇인가? |
| 같은 제품에서 같은 목적·시간으로 | 고객은 같은 목적이나 같은 시간을 두고 무엇과 비교하는가? |

자료에 없는 고객 욕구를 질문의 답으로 창작하지 않는다. 질문은 가설 후보를 넓히는 도구이며, 실제 근거는 별도로 확인한다.

## 후보 만들기

서로 다른 역할을 가진 후보를 만든다.

- **문제 제거형:** 고객이 겪는 부담·낭비·불안을 없애는 관점
- **새로운 가능성형:** 이전에는 어렵던 행동을 가능하게 하는 관점
- **관계·역할형:** 고객의 과정에서 상품·브랜드가 맡는 역할을 새로 정의하는 관점

각 후보에 다음을 붙인다.

```text
후보 이름:
한 문장:
고객 근거:
제공자의 실제 강점:
이 컨셉이 바꾸는 선택:
미확인 사항:
```

## 압축하기

1. 고객이 이해해야 할 핵심 뜻을 먼저 보존한다.
2. 같은 뜻의 반복과 내부 전문용어를 줄인다.
3. 읽었을 때 제품·경험의 방향이 떠오르는지 확인한다.
4. 짧아졌지만 뜻이 모호해지면 다시 풀어 쓴다.

## 선택 검증

컨셉 후보 자체를 실제 고객 반응이나 시장 수요의 증거로 쓰지 않는다. 중요한 결정이라면 다음 중 가장 작은 확인을 고른다.

- 기존 고객 인터뷰에서 뜻이 어떻게 이해되는지 확인
- 같은 상품 설명에서 컨셉만 달리한 반응 비교
- 내부 팀이 같은 기능·콘텐츠 선택을 하는지 판단 일치도 확인
- 현재 운영 조건에서 약속을 실제로 지킬 수 있는지 검토

참고 관점: 호소다 다카히로, 《컨셉수업》. 위 질문과 절차는 원문 사례를 재배포하지 않고 실무 컨셉 설계에 맞게 독자적으로 재구성했다.
