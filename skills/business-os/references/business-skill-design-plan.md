# 공용 비즈니스 판단 기준

사업의 고객·돈·전환 병목이 불명확하거나 다음 검증 행동을 정해야 할 때 사용한다.

## 판단 순서

1. 현재 사업 폴더의 `.business/business-brief.md`가 있으면 읽는다.
2. 확정된 결정·현재 고객·상품·날짜를 보존한다.
3. 없는 정보는 판단에 필요한 것만 확인한다. 기록 요청 없이 브리프를 자동 생성하지 않는다.
4. 고객의 말·실제 지불자·현재 전환 경로·시도한 것·원하는 결과를 분리한다.
5. 자료로 뒷받침되는 병목을 정한다. 가격·후기·전환 수치를 지어내지 않는다.
6. 병목에 맞는 다음 행동이나 실험 하나로 좁힌다. 이미 팔고 있는 상품을 불필요하게 다시 설계하지 않는다.
7. 이번 단계에서 하지 않을 일을 정한다.
8. 검증 계획이 요청됐으면 가능한 기간·예산 안의 행동과 확인할 숫자를 제시한다.
9. 브리프 기록·갱신이 요청됐을 때만 사용자 확정 내용을 기록한다.

기본 출력은 고객 문제, 병목 또는 미확인, 필요한 다음 행동이다. 제작·발송·배포는 별도 실행 요청이 있을 때만 진행한다.

## 후속 작업 선택

| 현재 필요한 작업 | 목적지 |
|---|---|
| 시작 전 후보의 상세 비교 | `bi-solo` |
| 가격 조사·가격 후보 판단 | `pricing-decision-7steps` |
| 상품 제안·유입·퍼널·채널 전략 | `growth-marketing` |
| 브랜드 방향·포지셔닝 | `branding` |
| 브랜드·상품·서비스 컨셉 설계 | `concept-design` |
| 관찰된 고객 행동과 선택 가설 | `behavioral-science` |
| 콘텐츠의 심리 원리와 구조 | `content-psychology` |

후속 작업은 별도 범위다. 단계 통과만으로 제작·발송·배포를 자동 실행하지 않는다. 필요한 실제 데이터가 없으면 확인 필요로 남긴다.

## 사업 브리프 양식

브리프 생성·갱신 요청이 있을 때만 사용한다.

```md

## 기본 정보
- 사업/프로젝트:
- 마지막 갱신일:
- 현재 단계: 아이디어 / 파일럿 / 판매 중 / 개선 중

## 고객과 문제
- 핵심 고객:
- 고객이 말하는 문제:
- 실제 병목:
- 고객이 원하는 변화:

## 현재 제안
- 첫 상품 또는 현재 상품:
- 고객이 얻는 결과:
- 제공하지 않는 것:
- 가격 또는 검증 방식:

## 실행 경로
- 현재 고객 유입 경로:
- 전환이 끊기는 지점:
- 다음 실험:
- 확인할 숫자:

## 결정 기록
- 유지할 결정:
- 이번에 새로 결정한 것:
- 아직 모르는 것:
- 다음 검토일:
```
