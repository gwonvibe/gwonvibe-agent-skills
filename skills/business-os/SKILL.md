# Business OS

사업의 여러 문제를 한꺼번에 고치는 대신, 현재 결과를 가장 크게 막는 **병목 하나**를 찾는 스킬이다. 병목은 물이 흐르는 관에서 가장 좁은 부분과 같다. 다른 구간을 넓혀도 가장 좁은 곳이 그대로면 전체 흐름은 거의 좋아지지 않는다.

## 적용 범위

사용자가 다음을 요청할 때 사용한다.

- 매출·문의·전환이 막힌 이유 진단
- 무엇부터 검증하거나 고칠지 결정
- 여러 문제 중 우선순위 선택
- 사업 브리프 정리 또는 갱신

고객·상품·목표가 확정된 제작 요청, 오탈자·카피 수정, 가벼운 아이디어 대화에는 진단을 강제하지 않는다. 시작 전 사업 후보 비교는 이 스킬의 범위가 아니다.

## 먼저 확인할 자료

1. 대화에서 이미 확정된 고객·상품·가격·목표
2. 사용자가 제공한 매출·문의·방문·결제·환불·재구매 자료
3. 기존 사업계획서·브리프·결정 기록이 있다면 그 최신 내용

특정 폴더나 파일이 없다는 이유로 진행을 멈추지 않는다. 없는 정보는 현재 판단에 필요한 것만 확인하며, 이미 주어진 내용을 다시 묻지 않는다.

## 판단 순서

### 1. 고객과 결제자 구분

- 누가 문제를 겪는가?
- 누가 실제로 돈을 내는가?
- 고객이 자신의 말로 표현한 문제는 무엇인가?
- 고객이 원하는 변화와 현재 상품이 주는 결과는 무엇인가?

사용자와 결제자가 다르면 결제자의 선택 기준도 따로 본다.

### 2. 현재 흐름 그리기

실제 사업에 해당되는 단계만 적는다.

```text
고객이 알게 됨 → 관심·문의 → 결제 → 제공·사용 → 재구매·추천
```

각 단계에 확인 가능한 숫자·고객 발언·운영 기록을 붙인다. 자료가 없으면 `미측정`으로 남긴다.

### 3. 병목 하나 선택

`references/bottleneck-guide.md`를 사용해 처음으로 크게 막히는 구간을 찾는다. 단순히 전환율이 가장 낮은 구간을 고르지 않고 다음을 함께 본다.

- 목표 결과에 미치는 영향
- 근거의 신뢰도
- 지금 바꿀 수 있는 정도
- 해결 비용과 시간
- 다른 구간을 먼저 해결해야 하는지

근거가 부족하면 병목을 확정하지 말고 `가설`과 `확인할 자료`를 제시한다.

### 4. 다음 행동 하나 정하기

가장 좁은 병목을 확인할 수 있는 작은 행동 하나를 고른다.

- 무엇을 바꿀지
- 누구에게 적용할지
- 기간과 예산
- 확인할 숫자 또는 관찰
- 유지·중단·수정 기준

‘이번 주’나 ‘2주’는 예시일 뿐이다. 사용자가 제시한 기간·예산이 있으면 그것을 우선한다.

### 5. 이번에 하지 않을 일 정하기

병목과 직접 관련 없는 리브랜딩·웹사이트·앱·자동화·채널 확장은 보류한다. 진단 결과만으로 제작·게시·발송·광고 집행을 시작하지 않는다.

## 출력

요청 범위에 맞게 다음을 제시한다.

1. 보존할 확정 사실
2. 고객과 결제자
3. 현재 전환 흐름과 확인 가능한 근거
4. 가장 유력한 병목 또는 미확인 상태
5. 다음 검증 행동 하나와 측정 기준
6. 이번 단계에서 하지 않을 일

가격·후기·매출·전환 수치를 만들지 않는다. 이미 판매 중인 상품을 근거 없이 새 상품으로 다시 설계하지 않는다.

## 사업 브리프

사용자가 작성이나 갱신을 요청했을 때만 아래 항목을 사용한다. 추정을 확정 사실처럼 기록하거나 기존 결정·날짜를 덮어쓰지 않는다.

```markdown
# 사업 브리프

- 사업과 현재 단계:
- 핵심 고객 / 실제 결제자:
- 고객이 말하는 문제:
- 현재 상품과 가격:
- 고객이 얻는 결과:
- 현재 유입 경로:
- 전환이 끊기는 지점:
- 확인된 근거:
- 아직 모르는 것:
- 다음 검증 행동과 측정값:
- 이번에 하지 않을 일:
- 마지막 갱신일:
```

## 선택적 후속 연결

다른 스킬이 설치돼 있다면 시작 전 후보 비교는 `bi-solo`, 가정 반박은 `harden`, 가격 판단은 `pricing-decision-7steps`, 유입·퍼널은 `growth-marketing`, 브랜드는 `branding`, 구조적 방어력은 `moat-audit`로 이어갈 수 있다. 없어도 병목 진단과 다음 행동 결정은 이 스킬에서 끝낸다.

## 요청 예시

- “방문자는 늘었는데 결제가 그대로야. 지금 자료로 가장 먼저 볼 병목을 정해줘.”
- “문의는 많은데 계약이 안 돼. 확인된 사실과 가설을 나눠서 다음 실험 하나만 제안해줘.”
- “이번 달 매출이 떨어졌어. 사업 전체를 다시 만들지 말고 어느 단계가 막혔는지부터 봐줘.”
- “지금까지 확정한 내용으로 사업 브리프를 작성해줘. 모르는 내용은 추정하지 마.”
