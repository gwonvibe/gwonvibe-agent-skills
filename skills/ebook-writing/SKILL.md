# 전자책 기획·집필

전자책을 지식 목록이 아니라 독자가 실제로 한 가지 일을 해낼 수 있게 돕는 안내서로 만든다. 강의나 별도 설명 없이도 책만 보고 이해하고 따라 할 수 있어야 한다.

## 먼저 지킬 원칙

- 사용자가 요청한 범위만 작업한다. 목차 요청에 전체 원고까지 만들지 않는다.
- 어려운 용어는 처음 나올 때 쉬운 뜻, 일상적인 비유, 실제 예시 순서로 설명한다.
- 사실, 저자의 경험, 아직 확인하지 않은 가정을 구분한다.
- 통계·사례·인용·출처를 꾸며내지 않는다. 근거가 없으면 일반 원칙으로 표현하거나 확인이 필요하다고 표시한다.
- 분량보다 독자가 달성할 결과를 우선한다.
- 사용자가 지정한 파일이 없으면 임의의 폴더 구조를 만들지 않는다.
- 출간, 판매 등록, 외부 공유는 사용자가 요청한 경우에만 실행한다.

## 요청 범위 확인

다음 중 이번 요청에 해당하는 것만 수행한다.

- 기획: 독자, 문제, 도달 결과 정리
- 목차: 책의 진행 순서 설계
- 챕터: 한 장의 초안 또는 수정
- 전체 원고: 여러 장을 일관된 흐름으로 집필
- 검토: 이해도, 중복, 빠진 설명, 실행 가능성 점검
- 편집: 노션 등 특정 형식에 맞게 정리

## 작업 순서

### 1. 독자와 결과를 한 문장으로 정리한다

필요한 정보만 확인한다.

```text
독자: 이 책을 읽을 사람
현재 어려움: 지금 혼자 하기 어려운 일
읽은 뒤 결과: 책을 덮고 직접 할 수 있어야 하는 일
근거: 저자의 경험, 사례, 자료 중 사용할 수 있는 것
제약: 형식, 분량, 마감이 이미 정해졌을 때만 기록
```

빠진 정보가 있어도 안전한 가정으로 초안을 만들 수 있으면 가정을 밝히고 진행한다. 독자나 목표에 따라 결과가 크게 달라질 때만 짧게 질문한다.

### 2. 변화 경로를 만든다

`references/transformation-arc.md`를 사용해 아래 세 가지를 잇는다.

```text
현재 상태 → 필요한 단계 → 확인 가능한 도달 결과
```

막연한 목표보다 관찰 가능한 행동을 쓴다. 예를 들어 “마케팅을 이해한다”보다 “내 상품의 고객 한 명과 핵심 제안을 한 문장으로 적는다”가 낫다.

### 3. 구조를 고른다

`references/structure-patterns.md`에서 독자의 일에 맞는 기본 구조를 하나 선택한다. 여러 구조를 섞을 때도 책의 주된 흐름은 하나만 둔다.

각 장에는 다음 정보를 붙인다.

```text
장 제목:
이 장을 읽는 이유:
읽고 나서 할 수 있는 일:
필요한 선수 지식:
사용할 예시 또는 근거:
독자가 직접 할 행동:
완료 확인:
```

### 4. 한 장씩 쓴다

`references/chapter-writing.md`의 공통 뼈대를 사용한다. 한 장은 한 가지 주요 일을 맡게 하고, 설명 뒤에는 반드시 예시와 독자의 행동을 연결한다.

### 5. 독자가 끝까지 따라갈 수 있는지 점검한다

`references/completion-strategies.md`로 다음을 확인한다.

- 초반에 책의 쓰임과 도달 결과가 보이는가
- 필요한 선수 지식이 앞에서 설명되는가
- 예시 없이 추상적인 설명만 이어지지 않는가
- 막혔을 때 확인할 기준이나 해결 방법이 있는가
- 각 장을 마친 독자가 무엇을 했는지 확인할 수 있는가

### 6. 목적에 맞게 다듬는다

- 무료판과 유료판을 나눌 때: `references/free-vs-paid.md`
- 자연스러운 한국어 문장 검토: `references/korean-writing.md`
- 노션으로 배포할 때: `references/notion-format.md`

## 검토 결과 형식

원고를 검토할 때는 막연한 감상보다 수정할 위치와 이유를 함께 쓴다.

```markdown
## 잘 작동하는 점
- [구체적인 부분]: [독자에게 도움이 되는 이유]

## 먼저 고칠 점
1. [위치 또는 문장]
   - 문제: [독자가 막히는 이유]
   - 수정 방향: [어떻게 바꿀지]

## 빠진 설명
- [독자가 다음 행동을 하려면 필요한 정보]

## 수정 예시
[실제로 바꾼 문장이나 짧은 단락]
```

## 초보자가 바로 쓸 요청 예시

```text
이 전자책은 처음 온라인 상품을 만드는 1인 사업자를 위한 거야.
읽고 나면 자기 상품 소개 문구를 직접 쓸 수 있어야 해.
어려운 마케팅 용어는 쉬운 말과 예시로 풀어서 목차를 만들어줘.
```

```text
이 챕터를 강의 없이 읽어도 이해되게 고쳐줘.
처음 나오는 전문용어는 일상적인 비유와 실제 예시를 붙이고,
독자가 마지막에 직접 해볼 체크리스트도 만들어줘.
```

```text
내 원고를 검토해서 중복된 설명, 근거 없는 주장,
초보자가 건너뛰기 어려운 단계만 우선순위대로 알려줘.
아직 원문은 고치지 말아줘.
```
