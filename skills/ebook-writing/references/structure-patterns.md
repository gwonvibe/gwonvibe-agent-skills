# 전자책 구조 선택

구조는 멋있어 보이는 형식이 아니라 독자가 목표에 도달하는 순서다. 먼저 독자가 책을 어떻게 사용할지 정하고 맞는 기본 구조를 고른다.

## 네 가지 기본 구조

| 구조 | 잘 맞는 상황 | 기본 흐름 |
|---|---|---|
| 문제 해결형 | 원인과 해결책을 판단해야 할 때 | 문제 확인 → 원인 구분 → 해결 → 적용 → 점검 |
| 단계 실행형 | 결과물을 순서대로 만들어야 할 때 | 준비 → 첫 단계 → 다음 단계 → 통합 → 완성 확인 |
| 기준·참고형 | 필요할 때 항목을 찾아 써야 할 때 | 개념 지도 → 항목별 기준 → 예시 → 주의점 |
| 사례 학습형 | 실제 과정에서 판단을 배우는 것이 중요할 때 | 상황 → 선택 → 실행 → 결과 → 해설 → 독자 적용 |

## 선택 질문

1. 독자는 처음부터 끝까지 순서대로 따라 해야 하는가?
   - 그렇다면 단계 실행형을 우선한다.
2. 같은 문제라도 원인에 따라 해결법이 달라지는가?
   - 그렇다면 문제 해결형을 우선한다.
3. 책을 사전처럼 반복해서 찾아볼 가능성이 큰가?
   - 그렇다면 기준·참고형을 우선한다.
4. 정답보다 판단 과정이 중요한가?
   - 그렇다면 사례 학습형을 우선한다.

두 구조가 모두 필요하면 하나를 전체 뼈대로 두고 다른 하나는 장 안에서만 사용한다. 예를 들어 전체는 단계 실행형으로 구성하고, 각 단계의 선택을 사례로 설명할 수 있다.

## 목차 만들기

### 1. 마지막 결과를 적는다

```text
독자는 책을 덮은 뒤 [상황]에서 [결과물 또는 행동]을 완성한다.
```

### 2. 결과에 필요한 중간 산출물을 거꾸로 찾는다

예를 들어 최종 결과가 판매 페이지라면 고객 정의, 제안, 근거, 구성, 문장 초안이 먼저 필요할 수 있다.

### 3. 선수 지식 순서로 배열한다

뒤 장에서 사용하는 개념이나 결과물은 앞 장에서 설명하거나 만든다. 독자가 아직 모르는 말을 앞 장의 완료 조건으로 요구하지 않는다.

### 4. 각 장에 한 가지 역할을 준다

```text
장 제목:
독자가 해결할 문제:
만들 결과물:
앞 장에서 가져올 것:
다음 장에 넘길 것:
```

### 5. 선택 항목을 표시한다

모든 독자에게 필요하지 않은 내용은 본 흐름을 막지 않도록 “선택”, “해당할 때만”처럼 표시한다.

## 목차 검토

- 제목만 읽어도 진행 순서가 보이는가
- 서로 다른 장이 같은 일을 반복하지 않는가
- 초보자가 모를 개념을 설명 없이 사용하지 않는가
- 설명 장만 이어지고 실제 결과물을 만드는 장이 빠지지 않았는가
- 사례와 부록이 핵심 흐름을 대신하고 있지 않은가
- 각 장의 결과물이 최종 결과에 실제로 필요한가
- 도구 이름이 바뀌어도 남는 원리와 판단 기준이 있는가

장 수나 분량을 먼저 맞추지 않는다. 필요한 단계가 빠지지 않고 중복되지 않는지가 먼저다.
