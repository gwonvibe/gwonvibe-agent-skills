# 노션 전자책 편집 기준

노션 기능을 많이 쓰는 것보다 독자가 길을 잃지 않는 것이 중요하다. 핵심 내용은 기본 제목, 본문, 목록만으로도 읽혀야 한다.

## 기본 페이지 구조

```text
표지와 제목
이 책으로 얻을 결과
대상 독자와 필요한 준비
전체 목차
본문
부록과 참고 자료
업데이트 안내
```

본문의 각 장은 같은 순서를 반복한다.

```text
이번 장의 목표
핵심 설명
예시
따라 하기
막힐 때 확인할 것
완료 체크
다음 장 연결
```

## 기능 사용 기준

### 콜아웃

본문의 역할이 분명할 때만 사용한다.

- 핵심: 반드시 기억할 기준
- 주의: 실수나 안전 문제
- 예시: 설명용 또는 실제 사례
- 저자 노트: 개인 경험과 적용 범위

색이나 아이콘만으로 의미를 구분하지 말고 제목도 함께 쓴다.

### 토글

없어도 본문의 핵심 흐름을 이해할 수 있는 내용에 사용한다.

- 추가 설명
- 긴 예시
- 자주 묻는 질문
- 선택 과정

필수 단계, 안전 주의, 완료 기준은 토글 안에 숨기지 않는다.

### 체크리스트

행동이 끝났는지 확인할 때 사용한다. “이해하기”처럼 확인하기 어려운 말보다 결과물을 쓴다.

```text
[ ] 내 독자를 한 문장으로 적었다.
[ ] 독자가 읽은 뒤 할 행동을 적었다.
[ ] 첫 장의 예시를 내 주제에 맞게 바꿨다.
```

### 표

같은 기준으로 여러 항목을 비교할 때 사용한다. 문장이 길어져 읽기 어려우면 표 대신 소제목과 목록으로 나눈다.

### 이미지와 영상

- 장식보다 이해에 필요한 자료를 우선한다.
- 이미지에는 무엇을 봐야 하는지 설명이나 캡션을 붙인다.
- 영상에만 핵심 정보를 두지 말고 요약이나 단계도 본문에 쓴다.
- 외부 링크가 사라져도 책의 핵심 흐름은 남아 있어야 한다.
- 가능한 경우 자막이나 대체 설명을 제공한다.

## 탐색과 접근성

- 제목 단계는 순서대로 사용한다.
- 비슷한 장은 같은 이름 규칙을 쓴다.
- 긴 페이지에는 목차나 이전·다음 이동 링크를 둔다.
- 링크 문구는 “여기”보다 이동할 내용을 알려준다.
- 중요한 의미를 색상만으로 전달하지 않는다.
- 공유 권한과 외부 공개 범위를 배포 전에 확인한다.

## 배포 전 확인

- 로그아웃하거나 다른 계정에서도 필요한 페이지가 열리는가
- 링크와 임베드가 실제로 작동하는가
- 모바일에서 표와 이미지가 읽히는가
- 복제 허용 여부가 의도와 맞는가
- 개인정보, 비공개 메모, 편집자용 주석이 남아 있지 않은가
- 업데이트 날짜와 문의 방법이 실제 운영 범위와 맞는가
